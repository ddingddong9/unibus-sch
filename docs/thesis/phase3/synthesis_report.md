## 2. 핵심 주제

### 2.1 설계 인공물과 평가 증거의 결합

**근거 강도: 강함**

설계과학은 정보시스템 연구에서 문제에 적합한 인공물을 만들고 그 효용과 품질을 평가하는 활동을 함께 요구한다(Hevner et al., 2004)<!--ref:r01-hevner2004--><!--anchor:page:75-105-->. DSRM은 이를 문제 인식, 목표 정의, 설계·개발, 시연, 평가, 의사소통의 순환으로 구체화한다(Peffers et al., 2007)<!--ref:r02-peffers2007--><!--anchor:page:45-77-->. 두 자료를 함께 적용하면 UNIBUS의 연구 기여는 기능 수 자체가 아니라 캠퍼스 교통 문제를 역할·노선·데이터 모델로 구조화하고, 재현 가능한 시험으로 구현 상태와 한계를 증명하는 데 있다.

현장 운행 시험이 제한되었다고 해서 평가가 없어지는 것은 아니다. 대신 평가 범위를 정적 분석, 알고리즘 단위시험, API 권한 시험, DB lint, 빌드·번들 분석, Lighthouse 반복 측정으로 명확히 제한해야 한다. 이 선택은 운영 효과를 입증하는 현장 연구보다 낮은 외적 타당도를 가지지만, 프로토타입의 내부 일관성과 배포 가능성을 검증하는 데 적합하다.

### 2.2 위치 표시와 도착 예측은 서로 다른 성숙도 단계다

**근거 강도: 강함**

초기 GPS 기반 연구부터 대규모 AVL 구현, 구간 속도와 정차시간 모델, 위치 보정과 LSTM에 이르기까지 교통 예측 문헌은 도착시간이 단순 좌표 보간만으로 해결되지 않는다는 데 수렴한다(Lin & Zeng, 1999)<!--ref:r03-lin1999--><!--anchor:page:101-109-->; (Dailey et al., 2001)<!--ref:r04-dailey2001--><!--anchor:page:46-51-->; (Cathey & Dailey, 2003)<!--ref:r05-cathey2003--><!--anchor:page:241-264-->; (Sun et al., 2007)<!--ref:r06-sun2007--><!--anchor:page:62-72-->; (Han et al., 2020)<!--ref:r08-han2020--><!--anchor:page:42372-42383-->. 공통적으로 위치 품질, 노선 정합, 이동·정차시간, 과거와 실시간 상태를 결합한다.

따라서 UNIBUS의 ETA는 발표 시연과 인터페이스 검증을 위한 결정론적 추정으로 정의하는 것이 타당하다. 차량이 편집된 경로 위를 일정한 규칙으로 이동하고 남은 경로 길이와 설정 속도로 ETA를 계산하는 현 구조는 시각적·기능적 일관성을 검증할 수 있지만, 교통량과 승하차 변동을 예측하지는 않는다. 실제 운영 단계에서는 GPS 표본을 도로·노선에 정합하고(Newson & Krumm, 2009)<!--ref:r07-newson2009--><!--anchor:page:336-343-->, GTFS 또는 이에 준하는 정적 식별자와 실시간 상태를 연결하는 확장이 필요하다(Elliott & Lumley, 2020)<!--ref:r09-elliott2020--><!--anchor:page:153-167-->.

### 2.3 3D 시각화의 가치는 공간 맥락에 있고, 완전한 디지털 트윈과는 구분된다

**근거 강도: 중간**

스마트 캠퍼스와 이동 디지털 트윈 연구는 3D 객체를 데이터베이스·서버·센서 상태와 연결할 때 정적 모형 이상의 관리 인터페이스가 된다는 점에 수렴한다(Hu, 2023)<!--ref:r10-hu2023--><!--anchor:page:937-945-->; (Chen et al., 2024)<!--ref:r12-chen2024--><!--anchor:page:553-561-->; (Liu et al., 2023)<!--ref:r11-liu2023--><!--anchor:page:170-177-->. UNIBUS에서는 정류장, 건물, 노선, 운행 차량을 같은 좌표계에 배치하고 2D/3D 전환 시 동일한 운행 상태를 공유하는 것이 이 가치를 구현한다.

다만 물리-디지털 동기성과 형상 충실도를 평가한 이동 디지털 트윈 연구와 달리, 현재 UNIBUS 3D 캠퍼스는 수작업 모델링과 시뮬레이션 데이터에 의존한다. GIS 기반 반자동 제작 파이프라인은 향후 실제 지형·건물 배치를 갱신하는 방안을 제시하지만(Xu et al., 2024)<!--ref:r13-xu2024--><!--anchor:page:1068-1084-->, 현재 결과를 측량 정확도의 실세계 복제본으로 해석할 수는 없다. 그러므로 논문에서는 `2D/3D 디지털 트윈 기반 프로토타입`이라는 용어를 사용하되, 운영형 디지털 트윈과의 차이를 명시한다.

### 2.4 역할별 통합과 표준 기반 운영 조건

**근거 강도: 중간**

캠퍼스 셔틀 응용 연구는 학생의 실시간 위치 확인과 관리자의 운영 기능을 하나의 서비스로 결합할 수 있음을 보여준다(Gonzales et al., 2024)<!--ref:r14-gonzales2024--><!--anchor:page:482-486-->. UNIBUS는 여기에 학내순환, 신창역 셔틀, 통학버스를 하나의 노선 모델로 연결하고 사용자·관리자·기사 화면을 분리한다. 이는 단일 차량 추적 앱보다 넓은 범위지만, 실제 기사 조작이 불가능하다는 학교 측 제약 때문에 운전 중 입력을 핵심 흐름에서 제거해야 한다.

GTFS Realtime은 차량 위치를 변경 시 또는 최소 30초마다 갱신하고 위치 자료를 90초 이내로 유지할 것을 권고한다(MobilityData, n.d.)<!--ref:s01-gtfs--><!--anchor:section:General%20Practices-->. UNIBUS의 45초 stale 판정은 사용자에게 오래된 상태를 구분하는 내부 규칙으로는 보수적이지만, 실제 단말이 해당 주기로 송신한다는 증거는 아니다. 운영 시에는 차량 단말 또는 별도 관제 장치가 자동 송신하고, 기사는 운행 전후 최소한의 확인만 수행하는 구조가 적합하다.

### 2.5 PWA 접근성과 보안은 편의·위험을 함께 만든다

**근거 강도: 강함**

서비스 워커와 웹 앱 매니페스트는 캐시·설치·독립 실행 경험을 제공해 별도 앱스토어 배포 없이 모바일 접근성을 높인다(World Wide Web Consortium, 2026a)<!--ref:s02-serviceworkers--><!--anchor:section:Abstract-->; (World Wide Web Consortium, 2026b)<!--ref:s03-appmanifest--><!--anchor:section:1-->. 이는 캠퍼스 사용자가 링크로 접근하고 홈 화면에 설치할 수 있는 UNIBUS의 선택을 뒷받침한다. 그러나 서비스 워커 캐시는 실시간 데이터까지 영구적으로 보장하는 수단이 아니며, 오프라인 상태에서는 마지막 상태와 현재 상태를 분명히 구분해야 한다.

데이터 계층에서는 PostgreSQL RLS와 Supabase의 노출 스키마 권고가 역할별 최소 권한의 근거를 제공한다(PostgreSQL Global Development Group, 2026)<!--ref:s06-postgresql-rls--><!--anchor:section:5.9-->; (Supabase, n.d.)<!--ref:s07-supabase-rls--><!--anchor:section:Row%20Level%20Security%20in%20Supabase-->. 반면 브라우저 localStorage에 30일 bearer token을 보관하는 현 방식은 OWASP의 세션 식별자 저장 권고와 충돌한다(OWASP Foundation, n.d.)<!--ref:s05-owasp-html5--><!--anchor:section:Local%20Storage-->. NIST가 요구하는 실패 인증 시도 제한도 현재 구현에서 확인되지 않았다(National Institute of Standards and Technology, 2025)<!--ref:s04-nist80063b--><!--anchor:section:3.2.2-->. 따라서 RLS와 서버 역할 검증은 긍정적 결과이지만 인증 저장·rate limiting 개선 전에는 보안이 완성되었다고 평가할 수 없다.

## 4. 지식 공백

1. **경험적 공백:** 순천향대학교 학생·관리자·기사의 실제 사용 자료가 없다. 학술제 시나리오 평가 후 별도 사용성 연구가 필요하다.
2. **운영 공백:** 기사 조작이 제한된 조건에서 자동 위치 송신 단말의 배터리, 통신 끊김, 위치 누락 복구를 검증하지 못했다.
3. **예측 공백:** 실제 GPS·승하차·정차·교통 이력이 없어 ETA 정확도(MAE/RMSE)를 측정할 수 없다.
4. **공간 정확도 공백:** 3D 건물과 지형은 시각적 재현이며 측량·BIM·GIS 기준의 위치 오차를 평가하지 않았다.
5. **보안 공백:** 정적 점검과 권한 API 시험은 수행했으나 전문 침투시험, 부하 공격, 공급망 서명 검증은 범위 밖이다.
6. **외적 타당도 공백:** 두 공개 경로의 Lighthouse 측정과 시뮬레이션 시험은 실제 저사양 모바일·혼잡 네트워크를 대표하지 않는다.

## 6. 이론적 통합과 논문 논지

UNIBUS는 설계과학의 인공물로서 세 층을 결합한다. 첫째, 통합 데이터 층은 노선·정류장·차량·사용자·운행 상태를 연결한다. 둘째, 운영 서비스 층은 관리자 편집, 역할 권한, 위치 상태, 일정 계산을 제공한다. 셋째, 표현 층은 같은 상태를 사용자용 2D 지도와 3D 캠퍼스, 관리자·기사 화면에 맞게 변환한다. 이 구조가 연구질문 1과 3에 답한다.

연구질문 2의 답은 제한적이다. 21개 알고리즘 시나리오, 빌드·정적 검사, 원격 DB lint, 비인증 권한 시험, Lighthouse 반복 측정은 프로토타입의 기능·배포·기본 보안이 재현 가능함을 보여준다. 그러나 실제 ETA 정확도, 현장 사용성, 운행 안전성은 증명하지 못한다. 최종 논문은 이 경계를 결론과 한계에서 반복해 명시해야 한다.

## 7. 통합 분석의 한계

- 표적 범위 조사이므로 모든 교통·디지털 트윈 문헌을 포괄하지 않는다.
- 일부 논문은 출판사 자동 접근 제한으로 전체 본문 대신 DOI 메타데이터와 공개 초록을 중심으로 검증했다.
- 빠르게 바뀌는 웹 표준과 플랫폼 문서는 2026년 7월 15일 기준 버전을 인용한다.
- 공식 제품 문서는 구현 방법의 근거이지 독립적인 효과성 연구가 아니다.
