# UNIBUS 보안 검토 기록

## 1. 검토 범위

- 프론트엔드 인증 토큰 저장·전송
- Edge Function의 인증·역할 검사
- Supabase RLS와 SECURITY DEFINER 함수 권한
- CORS 및 Vercel 응답 헤더
- 패키지 공급망과 추적 파일의 비밀정보 패턴
- 기본 계정, 로깅, 로그인 실패 제어

자동 도구의 “0건” 결과는 취약점 부재의 증명이 아니므로 코드 검토와 비인가 요청 시험을 함께 수행했다.

## 2. 확인된 방어

- 세션 토큰은 CSPRNG 32바이트로 생성하고 DB에는 SHA-256 해시를 저장한다.
- 토큰 만료를 서버에서 확인하며 로그아웃 시 해시 및 이전 평문 토큰을 삭제한다.
- 관리자와 기사 API는 요청마다 DB의 현재 사용자 역할을 다시 조회한다.
- 버스 위치 갱신은 기사 또는 관리자 권한과 배정 상태를 서버에서 검사한다.
- `users`, `auth_tokens`, `bus_trips`, `route_path_cache`는 anon 직접 조회 정책이 없다.
- 노선·정류장·버스 위치처럼 사용자 화면에 필요한 항목만 공개 SELECT 정책을 둔다.
- 위치 기록 RPC는 PUBLIC 실행 권한을 회수하고 `service_role`에만 부여한다.
- 임의 Origin의 CORS preflight를 거부한다.
- Vercel에서 MIME sniffing, iframe embedding을 차단하는 헤더를 설정한다.
- `.env.local`과 Edge Function `.env`는 Git에서 제외되며, 추적 파일에서 API 키·개인키 형식의 값은 발견되지 않았다.
- `npm audit`의 알려진 의존성 취약점은 0건이다.

## 3. 잔여 위험

### H-01 예측 가능한 기본 계정 자료

- 심각도: High
- 상태: 현재 트리 수정 완료, 운영 계정 확인 필요
- 근거: 검토 시점의 초기 시드 코드와 과거 SQL에 고정 관리자 주소와 예측 가능한 개발용 비밀번호가 포함되어 있었다.
- 영향: 해당 자격증명이 실제 원격 계정에 남아 있다면 관리자 권한 탈취가 가능하다.
- 제한: 본 검토는 실제 운영 계정의 현재 비밀번호를 시험하지 않았으므로 원격 노출 여부를 단정하지 않는다.
- 완료 조치: 고정 자격증명과 샘플 사용자를 현재 시드·SQL에서 제거했다. 관리자 시드는 Edge Function secret으로 이메일과 15자 이상 비밀번호를 제공할 때만 실행되며 응답에 자격증명을 포함하지 않는다.
- 남은 조치: 운영 관리자가 별도 강한 비밀번호로 교체했는지 확인하고 기존 세션을 무효화해야 한다. Git 이력에 있던 값은 공개된 것으로 간주한다.

### M-01 장기 세션 토큰의 localStorage 보관

- 심각도: Medium
- 상태: 설계 개선 대상
- 근거: 30일 세션 토큰과 사용자 정보가 `localStorage`에 저장된다.
- 영향: 동일 Origin의 XSS가 발생하면 토큰 탈취 위험이 있다.
- 완화: React 기본 이스케이프, 서버 역할 재검증, 해시 저장이 적용되어 있으나 탈취된 bearer token 자체는 만료 전까지 사용할 수 있다.
- 권고: HttpOnly·Secure·SameSite 쿠키 기반 세션 또는 Supabase Auth로 이전하고 만료·회전 시간을 단축한다.

### M-02 로그인 시도 제한 부재

- 심각도: Medium
- 상태: 설계 개선 대상
- 근거: 로그인 엔드포인트에 계정/IP 기반 rate limit, 지연 증가 또는 잠금 정책이 없다.
- 영향: 비밀번호 추측과 credential stuffing 대응력이 낮다.
- 권고: Vercel/Supabase 전단 또는 별도 저장소 기반 rate limiting, 실패 관측과 경보를 추가한다.

### L-01 CSP 등 현대적 브라우저 헤더 부족

- 심각도: Low
- 상태: 개선 대상
- 근거: `Content-Security-Policy`, `Referrer-Policy`, `Permissions-Policy`가 설정되지 않았다.
- 권고: 네이버 지도, 카카오, Supabase, Web Push에 필요한 Origin을 조사해 보고 전용 CSP부터 단계적으로 적용한다.

### L-02 인증 이벤트의 개인정보 로그

- 심각도: Low
- 상태: 개선 대상
- 근거: 회원가입·로그인 로그에 이메일과 이름이 포함될 수 있다.
- 권고: 운영 로그에서는 사용자 ID의 축약값 또는 요청 추적 ID만 기록하고 보존 기간을 제한한다.

### L-03 Edge Function의 TypeScript 검사 제외

- 심각도: Low
- 상태: 개선 대상
- 근거: 서버 진입 파일에 `@ts-nocheck`가 있고 현재 `npm run typecheck`는 Deno 함수 계약을 충분히 검증하지 않는다.
- 권고: Deno 전용 `deno check`를 CI에 추가하고 공통 타입을 명시적으로 공유한다.

## 4. 위험 요약

| 등급 | 건수 | 처리 원칙 |
|---|---:|---|

| Medium | 2 | 한계와 후속 보안 설계로 명시 |
| Low | 3 | 운영 배포 체크리스트에 포함 |
