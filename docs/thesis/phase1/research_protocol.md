## 2. 연구 배경과 문제 정의

순천향대학교의 학생 이동 서비스는 학내순환버스, 신창역 연계 셔틀버스, 지역별 통학버스처럼 운행 목적과 시간 규칙이 서로 다른 교통수단으로 구성된다. 이용자는 노선, 정류장, 운행 시간과 현재 상태를 여러 맥락에서 확인해야 하고, 관리자는 노선과 정류장, 버스, 공지, 사용자 권한을 일관된 데이터 구조로 관리해야 한다. 특히 신창역 연계 셔틀은 전철의 출발·도착 시각과 연동되고, 후문 도착 후 운행을 종료하거나 학내순환으로 전환하는 복수의 운행 변형을 가진다.

학교 측 확인 결과 버스기사가 운행 중 스마트폰 앱을 직접 조작하는 방식은 실제 운영에 적용하기 어렵다. 따라서 본 연구는 기사 조작을 전제로 한 실시간 추적의 효과를 입증하는 연구가 아니다. 대신 서로 다른 셔틀 운행 규칙을 하나의 데이터 모델과 사용자 인터페이스로 통합하고, 관리자 중심 운행 설정, 경로 기반 위치 시뮬레이션, 2D/3D 시각화, 예상 도착·출발 시각 계산을 구현한 프로토타입의 설계 타당성과 기술적 완성도를 평가한다.

## 3. 연구 질문

### 3.1 주 연구 질문

**기사의 직접 앱 조작이 제한되는 대학 셔틀 운영 환경에서, 이질적인 운행 규칙과 역할별 업무를 통합한 2D/3D 웹 기반 운행 정보 시스템을 어떻게 설계·구현하고 재현 가능한 기술 시험으로 검증할 수 있는가?**

### 3.2 세부 연구 질문

1. 학내순환, 신창역 연계 셔틀, 통학버스의 노선·정류장·시간 규칙과 일반 사용자·관리자·기사 역할을 어떤 공통 데이터 및 권한 구조로 통합할 수 있는가?
2. 경로 기반 위치 시뮬레이션, 예상 도착·출발 시각 계산, 2D/3D 전환 시각화는 사전에 정의한 기능 정확성·성능·보안 기준을 충족하는가?
3. 기사 직접 조작이 어렵다는 현장 제약을 고려할 때 관리자 설정, 자동 위치 수집 또는 차량 단말 연계로 확장 가능한 운영 구조는 무엇인가?

- 실제 버스기사의 운행 중 앱 조작 실험

- 관리자가 입력한 노선과 정류장 좌표는 운영 기준 정보로 취급한다.
- 시뮬레이션 위치는 실제 차량 위치가 아니며, 기능 검증과 발표 시연에만 사용한다.
- 실제 위치 수집을 도입할 경우 운전자 앱 대신 차량 단말, 전용 GPS 또는 백그라운드 위치 수집 장치가 필요하다.

## 6. 연구 방법론 청사진

### 6.1 연구 관점과 방법

- 연구 관점: 실용주의(pragmatism)
- 연구 유형: 설계과학 연구(Design Science Research) 성격의 단일 사례 프로토타입 연구
- 연구 방법: 요구사항 분석, 시스템 설계·구현, 정량 기술 평가, 시나리오 기반 기능 검증
- 분석 단위: UNIBUS 소프트웨어 아티팩트와 재현 가능한 실행 결과
- 사람 대상 연구: 수행하지 않음

프로토타입이라는 인공물을 설계하고, 현장 제약을 설계 요구사항으로 전환하며, 구현된 결과를 기술 지표와 시험 시나리오로 평가한다. 사용자 경험의 인과 효과나 실제 운영 성과는 추론하지 않는다.

### 6.4 시험 원칙

1. 측정 전 코드 커밋, Node.js 버전, 브라우저 버전, 장치 사양과 실행 명령을 기록한다.
2. 성능 측정은 개발 서버가 아닌 production build로 수행하고 최소 5회 반복한다.
3. 성능 결과는 평균만 제시하지 않고 중앙값, 최소값, 최대값을 함께 제시한다.
4. 인증이 필요한 화면은 동일한 테스트 계정과 초기 상태를 사용한다.
5. 시뮬레이션 데이터와 실제 운영 데이터를 명확하게 구분한다.
6. 실패한 시험을 삭제하지 않고 원인, 수정 내용, 재시험 결과를 추적한다.
7. 자동 검사 결과는 실제 보안성·사용성을 완전히 보장하지 않는다는 한계를 명시한다.

## 7. 타당도와 윤리

### 7.1 타당도 확보 전략

- 구성 타당도: 연구 질문의 각 개념을 기능·성능·보안 지표와 일대일로 연결한다.
- 내적 타당도: 측정 환경과 입력을 고정하고 동일 시험을 반복한다.
- 신뢰도: 명령, 스크립트, 원시 결과와 계산 과정을 논문 부록에서 재현 가능하게 제공한다.
- 외적 타당도: 순천향대학교 단일 사례이므로 다른 대학으로의 일반화를 주장하지 않고 이전 가능 조건만 논의한다.
- 증거 삼각검증: 코드, 데이터베이스 스키마, 실행 화면, 자동 측정 결과를 교차 확인한다.

### 7.2 윤리 및 개인정보

- 실제 사용자 연구와 개인 위치 추적을 수행하지 않으므로 사람 대상 연구 결과를 보고하지 않는다.
- 화면 캡처에는 실제 학생 이름, 이메일, 학번, 토큰, 키 또는 정확한 개인 위치를 포함하지 않는다.
- 테스트 계정과 가상 버스 데이터를 사용하고, 식별 가능한 값은 가리거나 대체한다.
- 생성형 AI의 문헌 정리, 문장 보조, 코드·도식 생성 활용 범위를 논문에 공개하고 모든 인용은 원문으로 재검증한다.

## 9. 1차 반론 검토

### 판정: PASS WITH REVISIONS

#### 주요 문제와 대응

1. **프로토타입이 실제 운영 효과를 증명하지 못한다.**
   - 대응: 제목과 결론을 설계·구현 연구로 제한하고, 사용자 만족도·대기시간 감소·운영 효율 향상을 결과로 주장하지 않는다.
2. **시뮬레이션 ETA는 실제 교통 상황의 예측 정확도를 보여주지 못한다.**
   - 대응: ETA를 규칙 기반 표시 로직의 결정성·경계조건 정확성으로만 평가하고, 예측 모델 정확도와 구분한다.
3. **3D 시각화가 기능적 필요보다 발표용 장식으로 보일 수 있다.**
   - 대응: 정류장 공간 인지, 캠퍼스 경사·랜드마크 기반 방향 파악, 2D/3D 정보 일관성이라는 설계 목적을 정의하고 성능 비용도 함께 측정한다.
4. **단일 개발 장치의 성능 측정은 일반화가 어렵다.**
   - 대응: 장치·브라우저·네트워크 조건을 공개하고 결과를 비교 지표가 아닌 사례 측정으로 제한한다.

#### 가장 강한 반론

“실제 기사와 학생이 사용하지 않은 시스템은 대학 셔틀 운영 문제를 해결했다고 볼 수 없다.”

본 연구가 답할 수 있는 범위는 실제 문제 해결의 효과가 아니라, 현장 제약을 반영한 통합 프로토타입의 구현 가능성과 기술 시험 결과이다. 실제 운영 효과는 차량 단말 연동과 학교 승인 이후의 후속 현장 연구로 남긴다.

## 10. 연구 완료 기준

- 국문·영문 초록과 7~8개 주제어 포함
- 20쪽 이상의 본문 및 순천향대학교 안내서 기반 편집 형식 적용
- 표·그림 목록과 3개 이상의 시스템 도식·실제 화면 포함
- 검증된 학술·표준·공식 기술 문헌 15개 이상 인용
- 실행 명령과 원시 결과를 남긴 기능·성능·보안 평가
- 실제 사용자 연구 부재와 운영 제약을 명시한 한계 절
- DOCX와 PDF 전 페이지 렌더링 및 육안 검수 완료
